# Яндекс LMS внутри VS Code

Задания, учебники и уроки Яндекс LMS прямо в редакторе: теория и условие слева, код справа, отправка решения одной кнопкой, прогресс и оценки по курсу, ИИ-помощник, проверка PEP 8.

## Задания и решения

Два вида заданий: с кодом (условие в панели, файл решения в редакторе) и с вариантами ответа.

![Задание с кодом: условие слева, редактор справа](docs/screenshots/hero.png)

![Задание с вариантами ответа](docs/screenshots/task-markers.png)

- **Дерево курсов** — курсы → уроки → материалы и задания со статусами: ✓ зачтено, ⟳ на проверке, ✎ на доработку.
- **Условие как на сайте** — форматирование, таблицы, картинки, в том числе картинки-ресурсы с кодом.
- **Файлы решений** — `yandex-lms/<курс>/<урок>/`, шаблон `def main(): pass` вырезается автоматически.
- **Отправка и вердикт** — одна кнопка и ожидание проверки; «Подробности»: вердикт, лог компиляции, время и память, ввод/вывод упавшего теста.
- **Плашка вердикта кликабельна** — под шапкой раскрывается причина: traceback/stderr, лог компиляции, ввод теста.
- **Задания с вариантами ответа** — вопрос, варианты, отправка своего или выбранного ИИ ответа.
- **PEP 8** — `pycodestyle`/`flake8`, а если их нет — `py_compile` и встроенные проверки.

## Прогресс и оценки

- **Прогресс прямо в дереве** — у урока и курса полоса `▰▰▰▱▱▱ 3/5 · 25/45 б.`; в подсказке — дедлайн урока и сколько обязательных задач просрочено.
- **Панель `LMS: Мои оценки`** — карточки «Зачтено», «Баллы», «На проверке», «Требует внимания», рейтинг курса из LMS и список уроков с задачами.
- **Фильтр «Только проблемы (N)»** — скрывает зачтённое: остаются задачи на доработке, без решения, просроченные и ждущие вердикта.
- **Дедлайны по-человечески** — «до 2 ноября 2026 г. · осталось 4 дня», а у просроченных красным «просрочено на 8 дней»; в строке задания — метка «просрочено».
- **Клик по задаче** в панели открывает её: условие и файл решения, как из дерева.
- **Дополнительные задачи** помечены: в подсказке задания — «Дополнительная задача», в карточке «Зачтено» — «из них дополнительных N»; в «Просрочено обязательных» на уроке они не считаются.
- **Оценки переживают перезагрузку окна** — компактный снимок курса хранится в `globalState`, в подсказке курса видно, когда он посчитан («Обновлено: 29 октября 2026 г.»).
- **По одному запросу на урок** (не больше 4 параллельно): баллы, статусы и дедлайны приходят уже в списке задач урока. Фонового обхода всех курсов нет — как и раньше.
- **Если webview сломан** — при баге #342842 панель не висит: те же цифры печатаются текстом в **Output → «Yandex LMS»**.

## Учебные материалы

Учебники и статьи LMS открываются в отдельной вкладке-читалке. При открытии материала остальные вкладки редактора закрываются (несохранённые файлы сохраняются), чтобы ничего не отвлекало от чтения.

- **Материалы в дереве** — внутри урока, рядом с заданиями; синяя иконка книги и тип материала («Учебник», «Статья», «Видео»).
- **Читалка в стиле VS Code** — липкая шапка с названием и типом, хлебные крошки «курс → урок», оценка времени чтения и полоса прогресса.
- **Оформление как на сайте** — заголовки, списки, таблицы, картинки, цитаты, врезки и блоки кода; у кода есть кнопка «Копировать».
- **Подсветка Python** — ключевые слова, строки, числа, функции и комментарии раскрашены как в редакторе VS Code, с отдельной палитрой для светлой и тёмной темы.
- **Оглавление и переходы** — внутренние ссылки из содержания прокручивают к разделу; кнопки «Предыдущий / Следующий материал» листают урок.
- **Обновить и открыть в LMS** — содержимое можно перечитать заново или открыть исходную страницу в браузере; при сбое сети показывается сохранённая копия.
- **Материалы урока списком** — команда `LMS: Материалы урока` из дерева или меню задачи.
- **Запасной режим, если webview сломан** — если панель не загрузилась за 4 секунды (баг VS Code #342842), материал сам открывается во встроенном предпросмотре Markdown: код подсвечивает VS Code, картинки и таблицы сохраняются. Совсем без webview — команда `LMS: Материал — текстом`; вернуться к панели — `LMS: Материал — панелью`.

## ИИ-помощник

Чат с ИИ живёт в панели задачи: переключатель «Текст / Код» в строке ввода решает, куда ИИ пишет ответ.

![Чат с ИИ в панели задачи: переключатель «Текст / Код» в строке ввода](docs/screenshots/chat-text.png)

- **Чат с ИИ** прямо в панели задачи: **Текст** — ответ в чате, файл решения не трогается; **Код** — правка файла решения, ответ на вопрос уходит в код комментарием `# …`.
- **Подсказки** — пошаговый план без готового кода.
- **Проверка решения** — разбор кода и что именно не так.
- **Готовое решение** — эталонный код по условию.
- **Исправление по ошибке** — чинит код по вердикту проверки LMS.
- **Выбор ответа** — для заданий с вариантами.
- **Автодополнение** в редакторе — следующая строка решения по условию.
- **Самопроверка** — запрещённые в курсе конструкции и компиляция Python с автоисправлением; правила курса настраиваются.
- **Память ошибок** — ИИ запоминает повторяющиеся промахи и не повторяет их.
- **Провайдеры** — OpenRouter, Mistral, OpenAI, Ollama, любой OpenAI-совместимый API, локальные агенты **OpenCode CLI** и **Cline CLI** (без ключа).
- **Пул ключей** — несколько ключей и провайдеров, ротация по лимитам, «остывание» по `Retry-After`, hedge-ускорение вторым ключом.

## Установка и сборка

```bash
npm test                 # 131 юнит-тест (node --test)
npm run package          # соберёт dist/yandex-lms-2.8.0.vsix
code --install-extension dist/yandex-lms-2.8.0.vsix
```

Артефакты сборки складываются в `dist/` (исторические версии — там же). Требуется Node.js 18+ и VS Code 1.85+.

## Вход

![Меню входа: QR, логин и пароль, cookie](docs/screenshots/login-menu.png)

1. **QR-код** — `LMS: Войти по QR-коду`: сканируйте приложением Яндекса, пароль и 2FA не нужны;
2. **логин и пароль** — для аккаунтов без 2FA;
3. **cookie** — если включена 2FA: DevTools (F12) → Network → Request Headers → скопировать строку `Cookie` для lms.yandex.ru.

Куки хранятся в `SecretStorage` VS Code. API-ключи ИИ — тоже (в `settings.json` не попадают; старый ключ из настроек переносится автоматически).

## Настройки

Всё настраивается в одной панели: **шестерёнка в шапке условия**, иконка в заголовке дерева курсов или команда `LMS: Настройки`. Разделы — «Аккаунт и LMS», «ИИ: провайдеры», «ИИ: поведение», «Диагностика»; изменения сохраняются сразу, ключи можно добавлять, проверять и удалять прямо в списке.

| Параметр | Описание |
|---|---|
| `yandexLms.apiBase` | адрес LMS (по умолчанию `https://lms.yandex.ru`) |
| `yandexLms.folderName` | папка для файлов решений (по умолчанию `yandex-lms`) |
| `yandexLms.pythonPath` | путь к Python для локального запуска и PEP 8 |
| `yandexLms.pollSeconds` | сколько ждать вердикт после отправки (60) |
| `yandexLms.taskView` | `panel` / `text` / `auto` — как показывать условие |
| `yandexLms.debug` | отладка: писать логи в `%TEMP%\yandex-lms-diag` (выкл. по умолчанию) |
| `yandexLms.ai.temperature` | температура генерации |
| `yandexLms.ai.opencodeBin` | команда/путь к OpenCode CLI (`opencode`) |
| `yandexLms.ai.clineBin` | команда/путь к Cline CLI (`cline`) |
| `yandexLms.ai.courseRules` | правила курса для ИИ (пусто = встроенные правила базового курса) |
| `yandexLms.ai.autocomplete` | ИИ-автодополнение (вкл.) |
| `yandexLms.ai.autocompleteDelay` | пауза перед запросом подсказки, мс (800) |
| `yandexLms.ai.autocompleteMaxCalls` | максимум запросов к ИИ в минуту (12) |
| `yandexLms.ai.selfCheck` | самопроверка и автоисправление кода (вкл.) |
| `yandexLms.ai.hedge` / `ai.hedgeDelay` | параллельный запрос ко второму ключу (вкл. / 7000 мс) |
| `yandexLms.ai.retries` | сколько ключей пула пробовать за запрос (3) |

## Отладка

Канал **Output → «Yandex LMS»** пишется всегда. Файлы в `%TEMP%\yandex-lms-diag` — только при включённой настройке `yandexLms.debug`; файлы старше 7 дней удаляются автоматически.

## Что изменилось в 2.8.0

**Прогресс и оценки по курсу.** Раньше было видно только статус каждой задачи, а вопрос «сколько уже зачтено и где я отстаю» оставался на сайте. Теперь прогресс считается в расширении: полоса с баллами в дереве и панель `LMS: Мои оценки` с карточками, фильтром проблем и разбивкой по урокам.

- **Дерево** — у урока и курса строка вида `▰▰▰▱▱▱ 3/5 · 25/45 б. · просрочено 2`; у курса она появляется только когда посчитан весь курс (по команде «Мои оценки»), иначе в подсказке видно «Посчитано по N раскрытым урокам».
- **Панель «Мои оценки»** — открывается иконкой графика в шапке дерева (в меню «…» справа вверху) или из контекстного меню курса; если курсов несколько, сначала спросит, по какому показывать.
- **Дедлайны** — дата в человеческом виде и остаток: «осталось 4 дня», у просроченных «просрочено на 8 дней» (красным в панели, меткой «просрочено» в дереве). В подсказке урока — «Просрочено обязательных: N».
- **Дополнительные задачи** (`isOptional`) отделены: в подсказке задания — «Дополнительная задача», в карточке «Зачтено» — «из них дополнительных N».
- **Один запрос на урок** — баллы, статусы и дедлайны приходят уже в списке задач урока, поэтому весь курс стоит по запросу на урок (не больше 4 параллельно). Данные переживают перезагрузку окна (`globalState`), при сбое webview оценки печатаются текстом в Output.
- **Заодно починено** — разбор списка задач урока вынесен в одну функцию (`flattenLessonTasks`): раньше плоский ответ без групп в дереве не показывался вообще.

## Что изменилось в 2.7.7

**Исправления по ревью 2.7.6.** Таймаут материала больше не влияет на панель задачи, повторный клик по материалу не закрывает соседние вкладки, а Lens не показывает устаревшую ошибку при повторном `Ctrl+Alt+G`.

- **Таймаут материала** — если учебник не успел отрисоваться за 4 секунды, на Markdown переходит только материал: общий флаг `webviewBroken` больше не выставляется, поэтому тихая перезагрузка условия после отправки остаётся панелью.
- **Повторное открытие материала** — уже открытый материал просто получает фокус, вкладка с решением рядом остаётся.
- **Вкладки** — при открытии задания сохраняется только предпросмотр текущего материала, а не любая вкладка `markdown.preview`.
- **Lens** — повторный запуск отменяет предыдущий захват, поэтому через 25 секунд не появляется устаревшее «webview не вернул снимок»; временный HTML со снимком удаляется через 2 минуты.
- **Чистка** — удалён неиспользуемый код разбора ревью и PEP 8.

## Что изменилось в 2.7.6

**Google больше не открывает пустой AI Mode без запроса.** При отправке одного только снимка Google Lens перенаправлял на `udm=26` — страницу AI Mode с надписью «Дополните запрос» и пустым «Обзором от ИИ». Теперь вместе с картинкой уходит текстовый запрос: название задания плюс «реши задачу». Google переключается на `udm=24&lns_mode=mu` и показывает нормальную страницу с распознанным условием и визуальными совпадениями.

- **Запрос в форме** — скрытое поле `q`; в панельном режиме тот же `q` добавляется в multipart-запрос.
- **Снимок не меняется** — PNG, размеры и проверка сигнатуры остались прежними; настройки `yandexLms.lens.openIn` и `yandexLms.lens.scale` работают как раньше.
- **Если Google всё равно показывает проверку на робота** — откройте `lens.google.com` в браузере, при необходимости обновите гостевые куки в настройках или включите VPN.

## Что изменилось в 2.7.5

**Снимок отправляется в Google из браузера, а не из процесса расширения.** Раньше PNG загружался из VS Code, а страница результатов открывалась в браузере без той же сессии Google: Google показывал битую картинку и пустой «Обзор от ИИ». Теперь `Ctrl+Alt+G` делает снимок, открывает локальную страницу с ним и отправляет форму в Google Lens уже из браузера пользователя — куки, IP и сессия совпадают, результат открывается сразу после загрузки.

- **Проверка снимка** — перед отправкой расширение проверяет размеры и сигнатуру PNG, а в `Output → «Yandex LMS»` пишет размер и состояние файла.
- **Диагностика** — при `yandexLms.debug` последний снимок сохраняется в `%TEMP%\yandex-lms-diag\lens-last.png`.
- **Режим панели** — `yandexLms.lens.openIn = panel` по-прежнему загружает снимок из VS Code и показывает результат карточкой; браузерный режим теперь использует сессию браузера.

## Что изменилось в 2.7.4

**Снимок для Google Объектива больше не падает с «Tainted canvases».** Старый способ — SVG с `foreignObject` — в Chromium/Electron помечает canvas как «испорченный» даже без картинок, поэтому `toDataURL` всегда выбрасывал исключение. Теперь условие рисует локальная копия `html2canvas` (MIT, лежит в `media/`, без CDN): текст, заголовки, списки, таблицы, код и формулы попадают в PNG. Внешние картинки заменяются подписью «картинка не встроилась» — они не могут испортить снимок; если рендер всё же не удался, расширение повторяет попытку на белом фоне, а последний рубеж — обычный текстовый снимок.

- **Гостевые куки Google — автоматически.** Перед первой отправкой расширение само заходит на Google и Lens, забирает куки и только потом загружает снимок. Это снижает шанс проверки на робота; в настройках по-прежнему можно вставить куки из DevTools, обновить их, проверить связь и очистить.
- **Куда открывать результат** — `yandexLms.lens.openIn`: браузер по умолчанию или панель VS Code со снимком и ссылкой.
- **Масштаб снимка** — `yandexLms.lens.scale` (1–3, по умолчанию 2).

## Что изменилось в 2.7.3

**Учебник открывается даже при сломанном webview.** В VS Code 1.141–1.142 первый webview окна падает на регистрации service worker, и панель материала оставалась пустой, а расширение тратило 18 секунд на бесполезные пересоздания. Теперь у читалки один короткий заход (4 секунды); если `ready` не пришёл, материал автоматически открывается во встроенном предпросмотре Markdown. Этот webview VS Code создаёт с `disableServiceWorker: true`, поэтому баг его не задевает: работают заголовки, списки, таблицы, картинки, ссылки и блоки кода с подсветкой Python от самого VS Code.

- **`LMS: Материал — текстом`** — последний рубеж: обычный `.txt` в редакторе, без webview вообще.
- **`LMS: Материал — панелью`** — ещё раз попробовать богатую читалку, когда webview починили.
- Уведомление после сбоя предлагает **«Починить webview»** (очистка Service Worker после того, как вы сами закроете VS Code), **«Открыть текстом»** и **«В браузере»**.
- После сбоя панели материала задачи тоже сразу открываются текстом — без ожидания таймаута.
- Временные `.md`/`.txt` материалы удаляются при запуске вместе с остальным кэшем.

## Что изменилось в 2.7.2

**Два исправления статусов и вкладок.** VS Code отдаёт тип webview-вкладки с префиксом `mainThreadWebview-`, из-за чего защита панели учебника не срабатывала: материал закрывался вместе с остальными вкладками и открывался заново. Теперь префикс учитывается — учебник остаётся единственной вкладкой с первого раза, а задача после него открывается как обычно.

**Панель больше не врёт «не отправлено».** Если решение уже отправлено и ждёт проверки, но вердикта ещё нет, плашка показывает **«На проверке»** — как и дерево. Статус берётся из отправленного решения или из общей карты статусов LMS, а не только из вердикта.

## Что изменилось в 2.7.1

**Починили «учебник не открывается».** При открытии материала панель могла закрыться вместе с остальными вкладками — теперь она защищена, а если всё-таки исчезнет, откроется заново. В канал **Output → «Yandex LMS»** добавлен короткий след открытия (id материала, тип панели и список вкладок), по нему видно, на каком шаге всё останавливается.

## Что изменилось в 2.7.0

**Учебники LMS теперь можно читать в VS Code.** Раньше материалы урока были видны только на сайте: в дереве расширения их не было вообще, а в задании — только условие. Теперь материалы грузятся вместе с заданиями урока и открываются в отдельной вкладке-читалке:

- дерево показывает материалы над заданиями: иконка книги, тип и название без служебного префикса «Учебник | …»;
- читалка оформлена в стиле панели задания: липкая шапка, тип, хлебные крошки, время чтения, прогресс прокрутки;
- сохранено оформление LMS: оглавление с якорями, врезки, цитаты, исправления, таблицы, картинки и блоки кода с кнопкой копирования;
- код в материалах подсвечивается как в VS Code: ключевые слова, строки, числа, функции и комментарии, отдельные палитры для светлой и тёмной темы;
- кнопки «Обновить», «В LMS» и переходы «Предыдущий / Следующий материал»; при ошибке сети показывается кэшированная копия;
- при открытии материала остальные вкладки закрываются — в рабочей области остаётся только учебник (файлы перед этим сохраняются);
- команда **`LMS: Материалы урока`** открывает список материалов урока, если из дерева это неудобно.

## Что изменилось в 2.6.0

**Google Объектив: снимок задания.** Условие задачи растрируется и отправляется в Google Lens, а найденный результат открывается в браузере или в панели VS Code — на выбор (`yandexLms.lens.openIn`). Куки Google запрашиваются при первом запуске и хранятся в SecretStorage, качество снимка регулируется настройкой `yandexLms.lens.scale`.

## Что изменилось в 2.5.3

**В списке заданий убран дедлайн.** Строка «до 11.01.2027» стояла в описании каждого задания и забивала список — теперь там только статус и баллы («Зачтено 25/25», «На проверке 0/1»). Сам дедлайн никуда не делся: он в подсказке при наведении на задание, в человеческом виде («Дедлайн: 11 января 2027 г.»).

## Что изменилось в 2.5.2

**Зачтённое решение больше не выглядит как «на доработку».** LMS отдаёт вердикт строчными — `ok`, — а код сравнивал его с `OK`. Из-за этого после успешной отправки:

- в дереве появлялся красный значок «на доработку», хотя решение принято;
- плашка в шапке панели была красной с сырым «ok» вместо зелёного «Зачтено»;
- уведомление показывало «LMS: ok» как предупреждение вместо «решение зачтено!».

Теперь вердикт сравнивается без учёта регистра (`ok`, `OK`, `accepted`, `accepted-after-deadline`), подписи ищутся так же, а вердикт важнее типа статуса: если LMS в списке задач пишет `rework`, а в решении вердикт `ok`, задача считается зачтённой. Для проверенных задач дерево дополнительно дотягивает вердикт из решения (по 4 задачи параллельно, чтобы не тормозить загрузку).

## Что изменилось в 2.5.1

**Исправлена отправка решения (403 на всех ручках).** Клиент искал CSRF-токен по имени куки в таблице, где ключ — `domain|path|name`, поэтому поиск всегда возвращал пусто и POST уходил без заголовка `X-CSRF-Token`. Сервер отвечал `403` на все изменяющие запросы (список курсов и задания при этом грузились — это GET). Что сделано:

- токен читается из куки правильно (при нескольких одноимённых куках берётся самая конкретная по домену);
- если куки нет (вход по QR или паролю её не получает) — расширение само забирает страницу LMS и берёт токен оттуда; то же происходит сразу после входа;
- на `403` токен обновляется и запрос повторяется один раз (без циклов), заголовки собираются заново на каждую попытку;
- в сообщении о неудаче теперь видно ответ сервера, а кнопка «Войти заново» открывает меню входа.

## Что изменилось в 2.5

**Чат с ИИ: два режима в строке ввода.** Переключатель «Текст / Код» стоит прямо в поле ввода (не отдельной панелью над ним), выбор запоминается между сессиями:

- **Текст** — нейросеть работает только с окном чата: ответ приходит сообщением в панель, файл решения не трогается;
- **Код** — нейросеть работает только с файлом решения и пишет только туда. Файл обязан измениться при каждом запросе: если вы задали вопрос, ответ уходит в код комментарием `# …` (или строкой в тройных кавычках). Метка времени в заголовке комментария гарантирует, что даже повторный одинаковый вопрос изменит файл, а не оставит «пустую» правку;
- после записи расширение проверяет, что код компилируется, и предупреждает в чате, если нет;
- при переключении режима черновик сообщения не теряется, фокус возвращается в строку ввода.

## Что изменилось в 2.4

**Настройки — в одном окне.** Раньше каждый параметр и каждый ключ настраивались цепочкой «пункт в палитре → поле ввода → ещё поле». Теперь есть панель с разделами и нормальными контролами:

- **ключи ИИ** — списком: маска ключа, модель, адрес, название; кнопки «Список» моделей, «Проверить», «Сделать основным», «Удалить»; общий «Проверить все» и «Сбросить лимиты»;
- **добавление провайдера** — формой (провайдер, адрес, ключ, модель с подсказками из API); для OpenCode/Cline — путь к бинарнику с проверкой версии;
- **поведение ИИ** — переключатели и числовые поля с единицами измерения, правила курса в многострочном поле;
- **поиск по настройкам** и ссылка на `settings.json` — в шапке панели.

Заодно id ключей в пуле стали стабильными: правка модели или ключа больше не отвязывает «основной» ключ, замеры времени и кулдауны.

## Что изменилось в 2.2

**Возвращено автозакрытие вкладок** (убрано в 2.0 как «навязчивое» — оказалось, это и был рабочий процесс):
- клик по иконке LMS закрывает все вкладки редактора (изменения сначала сохраняются) — остаётся только панель условия;
- открытие новой задачи закрывает окно кода предыдущей — одна задача, одно окно;
- заданиям с вариантами ответа окно кода не открывается, а прежнее закрывается;
- временные вкладки «условие.md» подчищаются, когда живёт панель условия.

## Что изменилось в 2.1

**Интерфейс**
- **липкая шапка панели задания**: статус решения (пилюля Зачтено / На проверке / Ошибка / не отправлено) и кнопка «Отправить решение» не уезжают при прокрутке условия;

## Известная особенность VS Code 1.142+

При перезагрузке окна первый webview может не загрузиться (`Could not register service worker: InvalidStateError`, [microsoft/vscode#342842](https://github.com/microsoft/vscode/issues/342842) — баг VS Code, ломает и встроенные расширения). Расширение справляется в три ступени:

1. если панель задачи не сообщила о загрузке за 2,5 секунды, она пересоздаётся со свежим service-worker scope (до 5 попыток); у материала попытка одна и короткая (4 секунды), чтобы не заставлять ждать;
2. если не помогло — условие открывается обычным текстом, а материал — во встроенном предпросмотре Markdown (он создаётся без service worker); сломанное состояние запоминается, и при следующих перезагрузках окна панель не открывается (ошибка не появляется) — работают команды «Материал — панелью», «Панель снова» и «Починить webview»;
3. если баг повторяется в каждом окне (кэш service worker побит) — команда **`LMS: Починить webview (очистить Service Worker)`**: вы закрываете VS Code сами (без принудительного убийства процесса), скрипт чистит `%APPDATA%\Code\Service Worker`, `Code Cache` и `GPUCache` и запускает VS Code обратно. Если VS Code не закрыт в течение 10 минут, скрипт молча выходит, ничего не удаляя.
